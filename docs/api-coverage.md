# Kernel API coverage — ntsim vs Speakeasy / KDemu / Qiling

Status after `fix/phnt-void-fidelity` (PHNT full headers, void fidelity). Sources consulted:
- PHNT: github.com/winsiderss/systeminformer/phnt/include/*.h (3078 NTSYSAPI/NTSYSCALLAPI, tie-breaker)
- Vergilius: vergiliusproject.com (kernel struct layouts for _EPROCESS/_ETHREAD/_KTHREAD/_OBJECT_HEADER)
- WDM: learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/* + ntdoc.m417z.com
- Speakeasy: github.com/mandiant/speakeasy (winenv/api/kernelmode/ntoskrnl.py; IAT-sentinel dispatch)
- hedgehog-tools/ktrace: github.com/struppigel/hedgehog-tools/tree/main/ktrace (void RAX preserve, trace suppression)
- KDemu: github.com/ShallowFeather/KDemu (real-dump memory + DbgEng-backed APIs, LIEF PE loading)
- Qiling: qilingframework/qiling wiki "Windows Emulation" (PE loader, virtual registry, rootfs DLLs)

## Signature fidelity (VOID vs NTSTATUS etc)

`packages/ntsim/src/winapi-meta.mjs` (generated by `tools/phnt-import.mjs` from `phnt/include/*.h`, pin `tools/phnt-pin.json`) is the single source of truth. `packages/ntsim/src/kernel.mjs:1005 defineApi` stores `apiMeta` and `1188 _installCpuHook` preserves `RAX` for `void` (Speakeasy + `hedgehog-tools/ktrace` semantics) and `packages/ntsim/src/tracer.mjs:212 finalizeTrace` suppresses `-> value` for void. `RtlInitUnicodeString` (`void`) no longer renders `-> 0x7fe78` (issue `driver_challenge.sys+0x1177`).

| Return class | Tracer | RAX | Example |
|---|---|---|---|
| `void` | no `->` | preserved (caller-owned) | `RtlInitUnicodeString`, `RtlCopyMemory`, `InitializeListHead`, `KeAcquireInStackQueuedSpinLock`, `KeReleaseInStackQueuedSpinLock` |
| `ntstatus` | `-> 0x0 (STATUS_SUCCESS)` | written | `IoCreateDevice`, `ObRegisterCallbacks`, `ZwCreateFile` |
| `boolean`/`pvoid`/`handle` | `-> hex` | written | `KeInsertQueueDpc`, `ExAllocatePoolWithTag` |

Auth via PHNT; MS docs + `ntdoc.m417z.com` consulted; conflicts resolved by PHNT.

RtlCopyBytes/memcpy/memmove/RtlMoveMemory (void vs pvoid split), RtlFillMemory (void)/memset (pvoid),
RtlZeroMemory (void), RtlCompareMemory

RtlEqualUnicodeString, RtlAnsiStringToUnicodeString, RtlUnicodeToUTF8
Lists: InitializeListHead (void), IsListEmpty (boolean), InsertHeadList (void), InsertTailList (void),
RemoveHeadList (pvoid), RemoveEntryList (boolean)

Process/thread: PsGetCurrentProcessId/Process/Thread, KeGetCurrentThread, IoGetCurrentProcess,
PsGetProcessId, PsLookupProcessByProcessId, PsLookupThreadByThreadId
Version: RtlGetVersion (ntstatus, was `return structVa`), PsGetVersion (boolean, was `19045n`)
Sync/time: KeInitializeSpinLock (void), Acquire/ReleaseSpinLock (void), KeAcquireInStackQueuedSpinLock (void, was provisioned `SUCCESS`), KeReleaseInStackQueuedSpinLock (void), KfRaiseIrql (kirql),
KeRaiseIrql (void)/LowerIrql (void), KeRaiseIrqlToDpcLevel (kirql), KeInitializeDpc (void),
KeInsertQueueDpc (boolean), KeSetTargetProcessorDpc (void, directed), KfReleaseDirectedDpcs,
KeQueryPerCpuIrql/KeQueryDpcQueueDepth (lab extensions), KfReadCr0/KfWriteCr0/
KfCli/KfSti (intrinsic shims), KeInitializeTimer (void), KeSetTimer/KeSetTimerEx/
CancelTimer (boolean), KeQueryTickCount (void)/SystemTime (void), KeStallExecutionProcessor (void),
KeDelayExecutionThread (ntstatus), KeWaitForSingleObject (ntstatus), KeBugCheckEx (void)
Objects: Ob(De)ReferenceObject (void), Obf(De)ReferenceObject (void), ObRegisterCallbacks (ntstatus), ObOpenObjectByPointer (ntstatus, was provisioned `SUCCESS` void confusion)
Registry: ZwOpenKey, ZwClose, ZwQueryValueKey, ZwQueryKey (+registrySeed helper), ZwCreateKey, ZwSetValueKey, ZwEnumerateKey/ValueKey etc (winapi-ext)
I/O: IoAllocateIrp/IoFreeIrp/IoCompleteRequest/IofCallDriver,
IoCreateDevice/IoCreateSymbolicLink (ntstatus), IoDeleteDevice/IoDeleteSymbolicLink
Resolution: MmGetSystemRoutineAddress (pvoid, PHNT-aware auto-provision)
Pre-existing: DbgPrint (ulong), KeGetCurrentIrql (kirql)

**Tier 2 auto-stubbed (`tools/phnt-import.mjs` + `winapi-meta.mjs`, 3078 total, Vergilius object model for handles):**
Every `NTSYSAPI/NTSYSCALLAPI` in `phnt/include/ntafd.h` ... `ntzwapi.h` (493), `ntrtl.h` (989), `ntpsapi.h` (62), `ntobapi.h` (24), `ntioapi.h` (50), `ntexapi.h` (126) etc not in Tier 1 is available via `provisionUnknownApi` with correct `ret` class. `MmGetSystemRoutineAddress` resolves them on demand. File objects, registry keys, sections, process/thread handles use `kernel.handles` + `kernel.fs`/`kernel.registry`/`kernel.sections` + Vergilius `_OBJECT_HEADER`/`_HANDLE_TABLE` layouts for `!handle` fidelity.
